# Playtest Notes

Requires the PlayDrop CLI. If the `playdrop` command is unavailable, follow the PlayDrop `setup` skill first.

Public creator and agent reference: https://www.playdrop.ai/docs/creator-tools/playtest-notes

## Core Contract

A Playtest Note is a creator-only handoff from the running game to an agent. Its primary content is custom context produced by the game runtime, such as creator-made content, a structured decision, or a corrected artifact. A creator-written message is optional supporting context.

Playtest Notes are not a second Update prompt. Use the normal Update flow when a prompt, current screenshot, and recent logs are enough. Use Playtest Notes when the runtime can send information or files that the Update flow does not know how to produce.

Build purpose-made controls such as **Save level for agent**, **Submit asset votes**, or **Send corrected spritesheet**. Do not add a generic Notes button whose main purpose is writing a message.

These controls may live in Playtest or in the optional owner-only Editor phase. Prefer Editor when the workflow needs persistent creator UI that would distract players. The same typed `sdk.creator.notes` contract applies in both phases.

## Required Runtime Design

1. Show the creator workflow only when `sdk.creator` exists.
2. Let the creator make, choose, review, or correct something inside the game.
3. Capture the useful result directly from runtime state. Do not ask the creator to describe data the game already has.
4. Make any creator message optional unless the typed SDK contract requires a comment.
5. Save the result with the exact `sdk.creator.notes` draft type that matches it.
6. Tell the creator what was saved and what the agent will receive.

Use uppercase kinds and exact typed draft shapes. JSON is `{ kind: 'JSON', value }`; images use `{ kind: 'IMAGE', image: Blob }`; exact assets use `{ kind: 'ASSET', assetRef, comment }`. There is no `title` field. Never cast the SDK to `any` to bypass these contracts.

## Reference Workflows

### 1. Level editor handoff

The creator builds or edits a level in the running game. A **Save for agent** action exports the complete level as JSON. The agent later integrates that JSON into the game source.

```ts
const creator = sdk.creator;
if (!creator) throw new Error('creator_tools_unavailable');

const message = messageInput.value.trim();

await creator.notes.add({
  kind: 'JSON',
  fileName: 'level-3.json',
  value: {
    type: 'level-editor-export',
    schemaVersion: 1,
    level: levelEditor.export(),
    ...(message ? { message } : {}),
  },
});
```

Include a stable `type`, a `schemaVersion`, and all data needed to load the level. Do not send only a description of the level.

### 2. Asset variation voting

The runtime presents asset variations generated by the agent. The creator votes each candidate up or down and may explain individual choices. Send the exact asset references and votes as JSON.

```ts
const creator = sdk.creator;
if (!creator) throw new Error('creator_tools_unavailable');

await creator.notes.add({
  kind: 'JSON',
  fileName: 'asset-variation-votes.json',
  value: {
    type: 'asset-variation-votes',
    schemaVersion: 1,
    votes: candidates.map((candidate) => ({
      assetRef: candidate.assetRef,
      vote: candidate.vote,
      ...(candidate.message ? { message: candidate.message } : {}),
    })),
  },
});
```

The votes and exact asset references are the primary context. Messages are optional explanations.

### 3. Spritesheet correction

The runtime provides an editor for moving misaligned frames and, when supported, fixing pixels. Export the corrected spritesheet as an image and export frame sizes, offsets, and other integration data as JSON.

```ts
const creator = sdk.creator;
if (!creator) throw new Error('creator_tools_unavailable');

const handoffId = crypto.randomUUID();
const correctedImage = await spritesheetEditor.exportPng();
const message = messageInput.value.trim();

await creator.notes.add({
  kind: 'IMAGE',
  image: correctedImage,
  fileName: `corrected-spritesheet-${handoffId}.png`,
});

await creator.notes.add({
  kind: 'JSON',
  fileName: `corrected-spritesheet-${handoffId}.json`,
  value: {
    type: 'spritesheet-correction',
    schemaVersion: 1,
    handoffId,
    imageFileName: `corrected-spritesheet-${handoffId}.png`,
    frames: spritesheetEditor.exportFrameData(),
    ...(message ? { message } : {}),
  },
});
```

Tell the creator that both saved items belong to one handoff and must be selected together. The corrected image and frame data are the primary inputs; the optional message only explains them.

## Choosing a Note Kind

- `JSON`: creator-made levels, votes, selections, alignment data, editor exports, and other structured runtime state
- `IMAGE`: corrected spritesheets, masks, paint-overs, or other edited raster artifacts
- `ASSET`: one exact PlayDrop asset reference with a required integration comment
- `LOG`: diagnostic output captured by the runtime
- `MARKDOWN`: structured text that is itself an artifact
- `TEXT`: plain text only when the text itself is the runtime result, not as a replacement for Update

## Consuming Context During an Update

- Auto and Local Agent tasks receive selected context automatically through the update prompt and task inputs. Treat structured data and attachments as the primary input.
- Task workers must use the selected context already attached to the task. They must not browse, clear, or replace creator state.
- Pending items retain the app version where they were authored and remain available across later versions until selected for a PlayDrop task or explicitly cleared.
- Check the authored version before interpreting coordinates, IDs, frame data, or other version-dependent context.
- Integrate the supplied result into the game source. Do not merely recreate it from an optional message.
- Test that the integrated level, asset choices, spritesheet, or other artifact works in the new version.

When working with Codex, Claude Code, or another external agent, inspect the exact app version with:

```bash
playdrop notes browse app:creator/name@1.2.3 --json
```

Use `--output <directory>` when attachments must be materialized locally. Clear only the explicit IDs actually incorporated, and only after the update is complete and tested. Do not clear removed, unrelated, or unread context.

Use the SDK and CLI help as the API reference.
