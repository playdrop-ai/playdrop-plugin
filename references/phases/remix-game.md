# Remix Game Phases

1. `setup`: claim a new slug when needed and scaffold with `./bin/playdrop project create app <slug> --remix <source-ref>`.
2. `study-source`: inspect the source assets/listing/catalogue and identify the main verb and strongest reusable pieces.
3. `remix-design`: define what changes: loop, constraint, fantasy, input, level structure, camera, or progression. Write it in `catalogue.json.design`.
4. `transform`: build the distinct version while preserving attribution and source ancestry.
5. `playtest`: run `./bin/playdrop project check .` with focused-frame actions to prove the remix is playable and meaningfully different.
6. `store-listing`: update hero art, icon, screenshots, description, tags, and references so they describe the remix.
7. `wrap-up`: validate, upload, and suggest next steps.

A remix is not a reskin. It should be recognizably derived but worth playing separately.
