# Remix Game Phases

1. `setup`: scaffold with `playdrop project create app <slug> --remix <source-ref>`.
2. `study-source`: inspect the source assets/listing/catalogue and identify the main verb and strongest reusable pieces.
3. `remix-design`: define what changes: loop, constraint, fantasy, input, level structure, camera, or progression. Write it in `catalogue.json.design`. If the remix changes the fantasy, surface, or visual promise, create its own art direction now (concept fields, heroes, board per `references/art-direction-board.md`); never inherit the source's stale ones.
4. `transform`: build the distinct version while preserving attribution and source ancestry.
5. `playtest`: run `playdrop project check .` with focused-frame actions to prove the remix is playable and meaningfully different, with evidence per `skills/playtest-game/SKILL.md`.
6. `store-listing`: update hero art, icon, screenshots, description, tags, and references so they describe the remix.
7. `wrap-up`: validate, upload or publish as instructed, and suggest next steps.

A remix is not a reskin. It should be recognizably derived but worth playing separately.
