# Store Listing & Metadata Accuracy

This dimension measures honesty and operational quality in how the game is presented on Playdrop. A good listing reduces confusion and sets the correct player expectation. A bad listing wastes traffic, creates distrust, and can actively misrepresent the runtime.

## Comparison discipline

Compare the listing to successful store pages for games in the same category. Strong references are not only aesthetically polished. They are accurate, clear, and representative.

Benchmark against:

- whether AI-generated marketing screenshots communicate truthful selling points supported by the playable build
- whether the listing video accurately represents literal gameplay
- whether the title and description communicate the real experience
- whether tags are useful and specific
- whether supported surfaces, auth requirements, remix info, and previewability are truthful

## What to inspect

- title and short description
- marketing screenshot promise and headline clarity
- gameplay video accuracy
- icon and cover fit
- whether the icon is square, text-free, and a dedicated close-up composition rather than the full hero, a crop of it, or a resize of it
- tags
- supported surfaces
- auth-required or previewable claims
- remix and asset attribution metadata when relevant

## Evidence to gather

- compare listing claims directly against the runtime and accurate gameplay video
- verify whether screenshots advertise unavailable mechanics, characters, environments, progression, rewards, or outcomes
- note stale metadata that likely reflects an older build
- capture missing or misleading tags that would affect discovery or player trust

## Questions to answer

- If a player clicks because of this listing, are they receiving what was promised?
- Does every screenshot selling point describe something the current version actually offers?
- Does the video accurately show the current version's gameplay?
- Are tags helping the right players find the game?
- Are technical metadata fields truthful?
- Is the listing written at the right level of specificity for the game's current stage?

## Common failure modes

- screenshots advertising content or capabilities absent from the current build
- raw gameplay captures published instead of finished AI-generated marketing screenshots
- video footage from an older or materially different build
- vague tags that say almost nothing
- unsupported surfaces claimed as supported
- previewability or auth settings misrepresented
- store copy that describes ambition rather than the current build

## Stage-aware interpretation

Early-stage games can still have honest listings. Marketing screenshots may be more polished and dramatic than runtime footage, but every selling point must remain true. The gameplay video provides the literal representation. A `First Release` is expected to have materially accurate metadata. A mature public game with sloppy metadata is leaving quality on the table.

## What strong feedback looks like

- "The screenshots advertise a progression system that the current game does not contain. The issue is the unsupported promise, not the higher level of visual polish."
- "The touch support tag should likely be removed or corrected because the current UI reads as desktop-first and does not actually feel touch-ready."
