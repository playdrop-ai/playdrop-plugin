# Store Listing & Metadata Accuracy

This dimension measures honesty and operational quality in how the game is presented on Playdrop. A good listing reduces confusion and sets the correct player expectation. A bad listing wastes traffic, creates distrust, and can actively misrepresent the runtime.

## Comparison discipline

Compare the listing to successful store pages for games in the same category. Strong references are not only aesthetically polished. They are accurate, clear, and representative.

Benchmark against:

- how honestly screenshots represent the playable build
- whether the title and description communicate the real experience
- whether tags are useful and specific
- whether supported surfaces, auth requirements, remix info, and previewability are truthful

## What to inspect

- title and short description
- screenshot honesty and clarity
- icon and cover fit
- tags
- supported surfaces
- auth-required or previewable claims
- remix and asset attribution metadata when relevant

## Evidence to gather

- compare listing claims directly against the runtime
- verify whether the screenshots overstate progress or hide the real experience
- note stale metadata that likely reflects an older build
- capture missing or misleading tags that would affect discovery or player trust

## Questions to answer

- If a player clicks because of this listing, are they receiving what was promised?
- Are screenshots representative of the actual current version?
- Are tags helping the right players find the game?
- Are technical metadata fields truthful?
- Is the listing written at the right level of specificity for the game's current stage?

## Common failure modes

- screenshots from an older or stronger-looking build
- vague tags that say almost nothing
- unsupported surfaces claimed as supported
- previewability or auth settings misrepresented
- store copy that describes ambition rather than the current build

## Stage-aware interpretation

Early-stage games can still have honest listings. In fact, honesty matters more when the build is early. A prototype can say "prototype" and still be well presented. A `First Release` is expected to have materially accurate metadata. A mature public game with sloppy metadata is leaving quality on the table.

## What strong feedback looks like

- "The game itself is roughly at demo quality, but the screenshots and copy currently imply a more complete release. The problem is expectation management, not only marketing polish."
- "The touch support tag should likely be removed or corrected because the current UI reads as desktop-first and does not actually feel touch-ready."
