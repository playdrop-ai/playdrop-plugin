# Mature Live Version

`Mature Live Version` means the game is no longer just a releaseable product. It is a maintained, iterated, credible live offering with broad competence across the key dimensions. The experience should feel like it has been learned from, improved, and shaped by real use, not merely launched once.

This gate is where recommendation and featuring conversations become realistic. A mature live game does not have to be massive, but it does have to feel durable and intentionally evolved.

## What is usually true at this gate

- the game has clear strengths across multiple dimensions
- improvements from iteration are visible in usability, content, retention, or overall polish
- performance and stability are dependable
- the product feels maintained rather than abandoned
- remaining issues are usually leverage issues, not foundational failures

## What is not yet true

- not every mature live version is exceptional
- the game may still have room to deepen, optimize, or broaden its audience
- some systems may still lag behind the strongest competitors, even if the overall product is credible

## Comparison discipline

Compare against strong live peers in the same category, especially those known for retention, clarity, trust, and recommendation value. This is where comparisons should become more demanding. A mature live game is not protected by "it is still early."

Ask:

- would this hold up in a recommendation rail beside strong peers?
- does the game show iteration quality, not just accumulated content?
- are the remaining weaknesses small enough that featuring or stronger recommendation treatment is plausible?

## Review expectations

At this gate, strong performance is expected in most dimensions:

- the loop should be dependable and rewarding
- retention or replayability should be meaningfully present
- controls and UX should be confidently solved
- listing quality should reinforce trust and discoverability
- runtime reliability should no longer be a regular concern

## Recommendation and featuring lens

This gate is where review should start thinking in recommendation terms.

Ask:

- would I trust this to represent Playdrop well in a recommendation context?
- are the strengths legible enough that a new player would understand why this is being highlighted?
- are the remaining weaknesses small enough that they would not undermine featuring confidence?

## Common misclassification risk

Do not assign this gate simply because the game has been public for a long time. Longevity without iteration quality is not maturity. The evidence must be in the product experience.

## Feedback framing

Feedback should be high-leverage:

- what would make the game stand out more clearly
- what would improve recommendation confidence
- what systems are holding back featuring potential
- where the creator should invest next for the greatest upside, not merely to fix basic problems
