# First Release

`First Release` means the game is complete enough to stand as a real public product on Playdrop. It may still need iteration, expansion, and polish, but the player should feel they received an honest and coherent version rather than a development artifact.

This gate is where public trust matters most. The game does not need to be mature. It does need to be genuinely releaseable.

## What is usually true at this gate

- the player can complete a meaningful session without unusual reviewer patience
- the listing and runtime are materially aligned
- the core loop, onboarding, controls, and runtime quality are good enough for broad exposure
- remaining issues feel like iteration work rather than rescue work

## What is not yet true

- the game may still be thin relative to long-term leaders in the category
- retention, content breadth, or live operations may still be developing
- some dimensions may still sit at "good enough" rather than "excellent"

## Comparison discipline

Compare against early public releases, early access launches, and first commercial versions of similar games. Ask whether players would understand this as a legitimate first release in that category, or whether it would still feel prematurely public.

The right question is not "is this finished forever." The right question is "is this a credible first public version?"

## Review expectations

At this gate:

- metadata accuracy matters strongly
- FTUE cannot be confusing
- performance and stability must no longer undermine ordinary play
- safety and trust standards must be fully met
- the review should begin to consider recommendability, not just basic acceptability

## Signals the gate is not yet earned

Be careful not to over-credit ambition. The build is not at `First Release` if one or more of these are still true:

- a typical new player would likely bounce before understanding the value of the game
- the listing still needs to apologize for the state of the build to remain honest
- restart, retry, save, or session flow still fail often enough to dominate the experience
- multiple dimensions are only acceptable if the reviewer imagines future fixes

## Common misclassification risk

Do not call a build `First Release` if it still depends on the creator's roadmap to explain why the current version matters. If the build still only proves potential, it is not at this gate yet.

## Feedback framing

Feedback should now help move the game from merely shippable to clearly good:

- quick wins should improve friction, clarity, and trust
- medium wins should strengthen depth, retention, or presentation
- next-level recommendations should point toward what would make the game meaningfully more recommendable or feature-worthy

The creator should come away knowing two things clearly:

- why the game is already a real release
- what separates it from becoming obviously good rather than merely acceptable
